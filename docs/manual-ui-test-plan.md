# 乐库整理助手真人操作测试方案

## 1. 测试目标

从普通用户视角验证当前本机安装版本的核心流程是否可理解、可完成、可恢复，重点检查：

- 用户能否明确知道当前文件状态和下一步操作。
- 后台任务是否有及时反馈，按钮是否正确启用或禁用。
- 导入、重命名、删除等文件操作是否具备预览、确认、校验和恢复能力。
- “文件缺失”“外部变化”和真实文件重新出现时，刷新与清理语义是否准确。
- 错误提示是否说明具体原因及解决方法，而不是只报告笼统失败。

## 2. 本轮环境与边界

- 操作工具：Codex 电脑插件，使用真实鼠标、键盘和 Windows 窗口状态观察。
- 应用入口：项目内 `manual_ui_test_harness.py`；SQLite、备份、歌单和运行记录只写入项目 `work/manual-ui-<timestamp>`，不访问已安装版生产数据。
- 待导入来源：`C:\Users\15180\Music\yinyve`。
- 导入目标：`C:\Users\15180\Music\音乐`。
- 测试前事实：来源目录 69 个音频文件，共 667,206,599 字节；目标目录为空；无同名冲突。
- 歌词夹具：用户尚未提供，本轮歌词扫描、匹配和歌词删除标记为 `SKIPPED`，不计为产品失败。
- 不访问其他音乐目录，不上传或分享媒体文件，不新增播放器或在线功能。
- 实际移动、删除到备份和永久清理必须在对应确认步骤前再次确认；未经确认只检查预览和文案。

## 3. 记录规则

每个用例记录：开始时间、操作路径、预期结果、实际结果、耗时体感、截图或可见文案、文件数量/哈希事实、结论和问题编号。

结论枚举：

- `PASS`：普通用户可顺利完成，结果与文件事实一致。
- `FAIL`：功能不可完成、结果错误、存在误操作风险或反馈明显误导。
- `BLOCKED`：受环境或确认条件阻塞，尚不能判断产品质量。
- `SKIPPED`：本轮明确不具备夹具或不在范围内。

问题等级：

- `P0`：可能丢失、覆盖或误删用户文件。
- `P1`：核心流程阻塞，或提示无法指导用户恢复。
- `P2`：明显不一致、反馈迟缓或操作成本过高。
- `P3`：轻微视觉或措辞建议，只进入 backlog。

## 4. 真人操作用例

| 编号 | 用户任务 | 操作摘要 | 通过标准 |
|---|---|---|---|
| UI-01 | 启动并理解首页 | 从桌面快捷方式启动，查看导航、文件总数、状态和主要按钮 | 5 秒内显示主窗口，无错误弹窗；刷新、排序、添加、删除含义清楚 |
| UI-02 | 搜索与排序 | 搜索中文/英文歌曲，清空搜索，切换排序 | 结果及时、清空可恢复、排序状态可理解且选择不混乱 |
| UI-03 | 重新同步来源目录 | 通过“导入 → 只读扫描已有音乐”选择来源目录 | 只读完成，不移动文件；69 个来源文件进入正确状态并记住目录 |
| UI-04 | 刷新异常记录 | 点击主页面“刷新”，观察缺失、外部变化及重新出现文件 | 重验已标记路径并刷新已记住目录；状态变化可解释，不出现笼统失败 |
| UI-05 | 生成导入预览 | 选择来源、目标和音频模式，生成只读预览 | 显示可执行、重复、冲突和失败数量；此时文件未移动 |
| UI-06 | 执行安全导入 | 确认预览并执行移动导入 | 每项大小与 SHA-256 校验后落位；目标 69 个、来源 0 个，无覆盖 |
| UI-07 | 查看导入历史 | 打开操作历史并查看文件级明细 | 能看到成功/失败、源目标路径和原因；最近完整导入可撤销 |
| UI-08 | 撤销最近导入 | 从历史执行撤销并确认 | 来源恢复 69 个、目标恢复为空；冲突时不覆盖且给出诊断 |
| UI-09 | 重命名体验 | 勾选测试音乐，打开重命名预览，不执行无意义改名 | 原名、建议、识别来源和状态清楚；无法识别项默认不执行 |
| UI-10 | 歌单流程 | 选择测试歌单根，新建歌单、添加和移除条目 | 只管理受管 `.lnk`；移除快捷方式不删除目标音乐 |
| UI-11 | 删除到备份与恢复 | 对测试文件查看删除确认，获确认后移动到备份并恢复 | 文案区分删除文件与清理记录；恢复不覆盖同名文件 |
| UI-12 | 缺失记录清理 | 对确实不存在的记录执行“清理记录” | 不访问或删除磁盘文件；索引审计保留，列表立即刷新 |
| UI-13 | 文件重新出现 | 让缺失路径重新出现后刷新，再尝试清理 | 刷新恢复为正常或外部变化；程序拒绝把真实存在文件当缺失清理 |
| UI-14 | 设置与维护 | 查看路径、备份保留期、重新检查和备份目录 | 显示真实已记住路径；维护任务状态明确；危险清理有二次确认 |
| UI-15 | 关闭与取消 | 在可取消后台任务中请求取消并关闭窗口 | 不再启动新批次；窗口最终正常关闭，不损坏索引或媒体 |
| UI-16 | 歌词完整流程 | 扫描 LRC、匹配、取消和删除引用检查 | 本轮无歌词夹具，记录为 `SKIPPED` |

## 5. 完善与复测门槛

- P0/P1 必须修复并重新执行对应失败用例。
- P2 中涉及误导反馈、明显重复操作或后台无响应的项目本轮修复；纯视觉建议记入 backlog。
- 修复不得降低文件安全门禁，不得直接删除索引审计，不得扫描用户未授权目录。
- 最终执行定向测试、全量单元测试、`compileall`、smoke、隔离环境 `pip check` 和 `git diff --check`。
- 若修改运行时代码，必须从最终运行时提交重新构建并验证本机安装、哈希、数据目录和桌面快捷方式。
